# OBJECTIVE

The Jurisdiction Agent must determine the legal/geographical jurisdiction relevant to the user's question.

Supported values:

```text
india
international
both
unclear
```

The agent must use:

1. Explicit jurisdiction selected by the user in the frontend, if available.
2. Explicit jurisdiction mentioned in the user's query.
3. Context from the conversation/query.
4. Only then infer jurisdiction when reasonably clear.

Do NOT make unsupported assumptions.

---

# IMPORTANT PRIORITY RULE

If the user explicitly selects a jurisdiction in the frontend, that selection has the highest priority.

For example:

```text
Frontend selection = India
User query = "How is this handled internationally?"
```

For the current request, use the explicit frontend selection only if the application's existing UX defines the selector as a hard filter.

If the selector is intended as a query context rather than a hard filter, preserve the user's explicit query intent and mark the result appropriately.

Inspect the existing frontend/backend implementation before deciding how the current selector works.

Do NOT redesign the selector.

# 4. UNCLEAR JURISDICTION

Do NOT automatically assume India just because the product is Ayurvedic or the user mentions Indian traditional knowledge.

Example:

```text

```

Expected:

```text
jurisdiction = unclear
```

The system should either:

* ask which jurisdiction the user is interested in, OR
* continue with a general answer while clearly identifying that jurisdiction-specific analysis requires clarification.

Prefer clarification when the legal answer would materially differ by jurisdiction.

Another example:

```text

```

Expected:

```text
unclear
```
